# Production and cloud roadmap

This plan separates application-runtime work from cloud-platform work so both
tracks can progress in parallel without editing the same files.

## Shared contract

The production entry point will be:

```text
sg run --config /config/experiment.yaml --run-root /work/runs
```

Successful runs exit with status `0` and produce:

```text
runs/<run-id>/
  config.yaml
  manifest.json
  status.json
  logs.jsonl
  shards/
  directions/
  measurements/
  report/
```

`run-id` is derived from the normalized experiment configuration and immutable
input identities. Stages write to temporary paths and publish outputs only
after validation. A repeated command resumes or reuses valid artifacts.

Run states are `CREATED`, `VALIDATED`, `EXTRACTING`, `MEASURING`, `ANALYSING`,
`REPORTING`, `SUCCEEDED`, and `FAILED`.

## Runtime engineering track

Owned paths:

- `python/scalar_geometry/`
- `python/tests/`
- `schemas/`
- `docs/runtime.md`
- Existing local CI checks when required by runtime changes

Deliverables:

1. A validated, versioned experiment configuration.
2. An immutable run identifier and directory contract.
3. Model identifier and revision pinning.
4. Automatic manifests containing input hashes, dependency versions, Git
   state, hardware metadata, stage timings, and output hashes.
5. Atomic stage publication, resumability, structured logs, and explicit exit
   codes.
6. `sg run` orchestration over extraction, measurement, subspace analysis, and
   report generation.
7. Unit and integration tests that require neither a network connection nor a
   model download.

## Cloud platform track

Owned paths:

- `infra/`
- `cloud/`
- `docker/`
- `.github/workflows/deploy.yml`
- `docs/cloud-deployment.md`

The cloud platform track must not modify runtime-owned paths until the runtime
branch is merged.

Deliverables:

1. Terraform for required APIs, Artifact Registry, one private artifact
   bucket, a BigQuery run ledger, a least-privilege service account, and a
   Cloud Run Job.
2. Bucket lifecycle and retention rules suitable for regenerable shards.
3. BigQuery tables for runs, scale measurements, and subspace summaries.
4. A cloud adapter that uploads a completed run directory and inserts only
   compact metadata and measurements into BigQuery.
5. Workload Identity Federation for GitHub Actions, with no service-account
   key committed or generated by the repository.
6. Build, deploy, execute, inspect, and teardown instructions.
7. A dry-run validation path that does not create billable resources.

## Integration order

1. Merge the runtime track.
2. Rebase the cloud track onto the runtime merge.
3. Replace any temporary cloud command with the final `sg run` contract.
4. Run local CI and Terraform validation.
5. Perform one deliberately small cloud run and retain its manifest, logs,
   BigQuery rows, and cost evidence.

The Remotion demonstration starts only after the first cloud run is verified,
so it can animate measured behavior rather than a proposed architecture.
